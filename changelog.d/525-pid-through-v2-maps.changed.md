- The HL7 v2 face maps PID to a `Patient`, and a `Patient` back into the PID of an ITI-21 answer, through the HL7 v2-to-FHIR structure maps of `ferrobridge-hl7v2` 0.2.0, in place of FerroPIX's own copy of them, and translates every table value (PID-8, the name type, the address type, the telecommunication use and equipment type) by `ConceptMap/$translate` on a FHIR R4 terminology server. Breaking for an operator of the HL7 v2 face: name the server in the new `[terminology]` section (`base_url`, `timeout_ms`, `[terminology.retry]`, `[terminology.credentials]` with HTTP Basic or the client credentials grant, and `[terminology.tls]`), loaded with HL7 Terminology, the guide's package `hl7.fhir.uv.v2mappings` 1.0.0 and FerroBRIDGE's value package; with `[hl7v2]` on and no `terminology.base_url` the server refuses to start. A feed or a query the terminology server does not translate is answered `AR`, so the sender sends it again. A cell phone (XTN-3 `CP`) is fed as a `phone` in `mobile` use, a number with no equipment type keeps a `system` carrying the data-absent-reason `unknown` where the face fed `phone` before, and an ITI-21 PID leaves XTN-2 empty on an email the `Patient` gives no `use`, where it wrote `NET`.
