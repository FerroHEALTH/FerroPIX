- Post-quantum JOSE signatures (RFC 9964). `[trust] post_quantum_only = true` verifies access tokens with ML-DSA-44, ML-DSA-65 or ML-DSA-87 alone: every issuer `algorithms` list left at the default becomes the three ML-DSA parameter sets, and a list naming another algorithm stops the start. The console's sign-in now accepts an ID Token signed with ML-DSA beside the classical algorithms, and its `[jose] post_quantum_only = true` accepts ML-DSA alone. A Nuts holder key may be an ML-DSA key, which signs the presentation with its parameter set where the Authorization Server lists it in `vp_formats` (the holder took only P-256 and P-384 keys before). The configuration page shows a `private_key_jwt` client with an ML-DSA-65 key. The post-quantum inventory states what `ferrohealth-smart` 0.35.0 accepts and signs on each JOSE row, counts those rows in the post-quantum configuration, and cites RFC 9881 and draft-ietf-tls-mldsa-06 for the TLS certificate row.
