- Breaking for a crate user: `ihe-iti` 0.1.0 requires `ferrohealth-smart` 0.16 (caret `0.16.0`) and `ihe-atna` 0.10 (caret `0.10.0`), and `nl-generic-functions` 0.1.0 requires `ferrohealth-smart` 0.16 and `ihe-iti` 0.1.0. Both name `ferrohealth-smart` and `ihe-atna` types in their public API, so the move of those public dependencies takes each crate's minor step, and a product on those lines needs this release; no signature of either crate moves. Upgrade: move `ferrohealth-smart` to 0.16.0 and `ihe-atna` to 0.10.0 beside them.
- Breaking for an operator: the server reaches the audit repository and the terminology server through `ferrohealth-smart`'s outbound client, each configured by its endpoint table, so the lock holds one copy of each family crate (`ferrohealth-smart` 0.16.2, `ferrohealth-session` 0.10.0, `ihe-atna` 0.10.0, `ferrohealth-config` 0.4.1, `ferrohealth-server` 0.8.1, `ferrobridge-term` 0.3.0, `ferrobridge-hl7v2` 0.5.0). Upgrade: write the audit repository as `[audit.endpoint]` with `url`, `timeout` and `[audit.endpoint.retry] max_backoff` (was `audit.url`, `audit.timeout_ms` and `audit.retry_max_ms`); its `max_backoff` is also the wait between two delivery rounds, and the table takes `connect_timeout`, `retry.max_attempts`, `tls` and `credentials` (HTTP Basic or the client credentials grant) as well. Write the terminology server as `[terminology.endpoint]` with `url`, `timeout`, `retry`, `credentials` and `tls` (was `terminology.base_url`, `timeout_ms`, `[terminology.retry]`, `[terminology.credentials]` and `[terminology.tls]`); compose and the Helm chart (0.3.16) name it `FERROPIX__TERMINOLOGY__ENDPOINT__URL` and `config.terminology.endpoint.url`. In this release each old key refuses the start and names its place under the endpoint table; from the next release each fails as an unknown key.
- A configuration the server or the console does not start on is refused with a line that opens `cannot start` (exit 78), and `healthcheck` with one that opens `not up` (exit 1), through `ferrohealth-server`'s run path; the server's line opened `the configuration is refused` before.
- `ihe-iti` 0.1.0 and `nl-generic-functions` 0.1.0 require the FerroBRIDGE crates by caret ranges, `fhir-search` `0.1.130` and `fhir-types` `0.1.130`, where `ihe-iti` 0.0.84 required `fhir-search` exactly, so a product whose other family crates take another compatible patch of them builds with one copy (#543).
