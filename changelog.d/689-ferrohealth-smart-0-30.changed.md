- A request past `server.max_concurrent_requests` now waits for a slot before it is refused: at most `server.admission_wait` (100 milliseconds by default) in a first-come queue of at most `server.max_waiting_requests` (256 by default; `0` keeps no queue). A full queue or an expired wait is still answered `503` with `Retry-After`, and the health routes are never refused or queued (FerroHEALTH/FerroSYS#403).
- Breaking for crate users: `ihe-iti` 0.15.0 requires `ferrohealth-smart` 0.30, and `nl-generic-functions` 0.15.0 requires `ferrohealth-smart` 0.30 and `ihe-iti` 0.15. Their public API carries smart's outbound client and endpoint table, so a consumer moves to the same lines. The server and the console move to `ferrohealth-smart` 0.30, `ferrohealth-server` 0.11, `ferrohealth-session` 0.25, `ferrobridge-term` 0.14 and `ferrobridge-hl7v2` 0.22, so one smart and one server link.
